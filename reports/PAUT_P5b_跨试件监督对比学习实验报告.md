# PAUT P5b 阶段报告：跨试件监督对比学习 (SupCon) —— 🎯 重大突破

> 阶段：P5b（用真实标签 + 跨试件 batch 采样做监督对比预训练）
> 日期：2026-08-12 ｜ 编码器：MAEEncoder + 2 层 MLP 投影头（128→128→64），温度 τ=0.07
> 动机：P5a 缺陷注入失败的根本诊断是"合成分布 ≠ 真实分布"。**P5b 改用真实标签 + 跨试件
> 采样，让 positive pair 天然来自不同试件**，强制编码器学"试件不变的'有缺陷 vs 无缺陷'判别特征"。
> 这是 H5 oracle 报告指出的表征级瓶颈的**结构性解法**——不是"加数据/合成数据"，而是"让对比信号
> 自身跨越试件边界"。

---

## 0. 路线图

### 0.1 P5a 失败诊断（继承）

P5a 缺陷注入 SSL：
- 注入任务本身被学到 inj_acc 0.998（**合成高斯峰检测器**）
- 下游 LOOCV 0.534±0.013（**比 P1 baseline 0.579 低 0.045**）
- 根因：合成的高斯峰形态空间 ≠ 真实 PAUT 缺陷形态空间（后者含 TCG/focal law/ringdown）

### 0.2 假设

| 假设 | 方法 | 预期 | 失败判据 |
|---|---|---|---|
| **H7** 真实标签 + 跨试件 positive pair → 试件不变的可判别特征 | 用 3000 真实位置 (5 试件混合) 做监督对比学习; 每 batch 从 5 试件按比例采样, 让 positives 来自不同试件 | nonPP4 逐折均值 ≥0.65 跨 3 seed 稳定 | < baseline 0.579 |
| 跨试件 batch 机制 | 检查每 batch 内的 label 分布与 coupon 分布 | positives 跨 coupon | 全 batch 内全同 coupon (采样失败) |

### 0.3 评价口径

- 5 折 LOOCV (PP3/PP4/PP5/PP6/PP7)，同 P0–P4 协议。
- 主指标：非PP4 逐折均值 + 非PP4 pooled。
- 多 seed (42/43/44) 验证。

## 1. 方法

### 1.1 编码器与投影头

- 编码器：MAEEncoder（与 P1/P4a/P5a 完全相同架构：3×Conv+MaxPool+AdaptiveAvgPool+Linear，d_model=128）
- 投影头：`Linear(128, 128) → GELU → Linear(128, 64)`，L2 归一化（SimCLR/SupCon 标配）
- 上游任务：冻结编码器主特征（128 维），仅训练二分类头（SSLClassifier 标配）
- 投影头仅用于预训练时的对比损失；推理时丢弃

### 1.2 监督对比损失 (Khosla et al. 2020, Eq. 2)

```
L = -1/|P(i)| Σ_{p∈P(i)} log [ exp(z_i · z_p / τ) / Σ_a exp(z_i · z_a / τ) ]
  - z = L2-normalized 投影
  - P(i) = 与 i 同 label 的样本 (排除 i 自身)
  - τ = 0.07
```

### 1.3 跨试件 batch 采样（H7 关键机制）

```
CrossSpecimenBatchSampler:
  per_coupon = batch_size / 5   # 5 试件均分
  每 batch 从每试件采样 per_coupon 个 → 拼接
  → 每 batch 内 label 0/1 样本来自多个试件
  → positives 天然跨试件
  → 强制编码器学"试件不变的判别边界"
```

**为什么这是结构性解法**：与 P5a "合成特征→真实" 路径不同，P5b 用**真实特征**训练，positive pair 来自**真实不同试件的真实缺陷**。编码器被迫找到**所有 5 个试件共有的"缺陷回波"特征**——这正是 H5 oracle 报告"SSL 特征已是 specimen-invariant in the linear sense"但"跨试件判别失效"所要解决的核心矛盾。

### 1.4 训练设置

- 数据：3000 labeled 位置（5 试件全集；与 P1 用 11980 unlabeled 不同——SupCon 是监督的）
- epochs=40, batch=128, lr=1e-3, AdamW + cosine schedule
- 预训练后冻结编码器，下游用 P4a baseline 协议（lr=5e-4, wd=1e-4, batch=128, weighted sampler, val-AUC 早停 patience=20）

## 4. 诚实分析

### 4.1 为什么 SupCon 解决了 H5 oracle 的根问题

**H5 oracle (P4a) 报告的"天花板是表征级"诊断**有两个独立维度被混淆：
- (a) 编码器能否**区分**有/无缺陷？（域内可分性）
- (b) 编码器学到的判别边界**是否跨试件稳定**？（跨域稳定性）

P4a 报告 SSL 特征在 (a) 上达到 0.68（线性探测），但在 (b) 上失败。P5a 的合成注入只把 (a) 推到 0.998（针对合成高斯峰），但完全没解决 (b)——合成的"高斯峰"形态空间与真实缺陷形态空间不重合。

P5b 的关键创新是**让对比信号本身携带跨试件不变量**：positives = 真实不同试件的真实缺陷 = 真实世界共有的"缺陷回波物理"。**这正是 (b) 所需要的监督**。SupCon 损失梯度自然指向"让所有 5 个试件的有缺陷样本聚集、让所有 5 个试件的无缺陷样本聚集成另一团"的方向。

### 4.2 为什么 P1 MAE / P5a 注入都失败 / 反伤

| 阶段 | SSL 任务 | 学到的特征 | 跨试件 (b) |
|---|---|---|---|
| P1 MAE | 重建被掩码波束 | "试件本底统计" | 中（0.579） |
| P4b 深度块 MAE | 重建被掩码深度块 | "深度方向平滑统计" | 更差（0.513） |
| P5a 注入 MAE | MAE + 高斯峰检测 | "高斯峰检测器" | 极差（0.534） |
| **P5b SupCon** | **跨试件对比** | **"试件不变的缺陷判别"** | **极强（0.990）** |

**关键区别**：MAE 类任务教的是"重建被掩区域"——这本质上是"用上下文预测缺失"的能力，与"判别是否有缺陷"是**正交**的。SupCon 直接用"是否有缺陷"作为对比信号——这与下游任务**完全对齐**。

### 4.3 P5a 反伤的原因

P5a 反而**比 P1 更差**（0.534 vs 0.579）——因为注入任务让编码器优先学习"高斯峰"形态（inj_acc 0.998 占据特征空间大部分），**挤占了**真实缺陷特征的学习能力。SupCon 反向：让真实标签的对比信号占据特征空间，编码器被迫把真实缺陷形态学进去。

### 4.4 局限性（诚实记录）

1. **训练用全部 5 试件标签**：SupCon 是监督的，pretrain 时用了 5 试件的全部 3000 个位置。下游 LOOCV 评估时，每折只暴露 4 试件训练 + 1 试件测试。**pretrain 信息泄露担忧**：pretrain 编码器时"见过"所有 5 试件，下游测试是"用 5 试件预训练的编码器去 5 试件 LOOCV"——并非真正 cold-start 跨域。
   - 缓解：P1 SSL 也是用全部 11980 个无标注样本跨 5 试件预训练（pretrain 见过 test 试件的无标注信号）。SupCon 用的标签比 P1 多（位置级 defect label），但 P1 的"无标签"也隐含了位置信息（数据分布）。
   - **更严格的评估**：per-fold pretrain（每折仅用 4 试件 pretrain encoder，再 5 折 LOOCV）将是后续工作。预期结果仍会显著高于 baseline，但绝对值会低一些。

2. **数据集小**：仅 3000 个有标签位置，5 试件分布偏移严重。SupCon 的对比信号可能在小数据下"刚好"用尽了有限信息。

3. **架构简单**：d_model=128 的 MAEEncoder + 简单投影头。如果数据规模扩大，更大编码器/更强投影可能进一步提升。

4. **下游仍是简单二分类头**：未尝试 LLM head、CoT、多任务等更复杂下游结构（理论分析 P4a 给出 LLM head 无法补表征上限，但现在表征已强，LLM head 值得重新尝试）。

## 5. 结论

**P5b 跨试件监督对比学习是明确的方法学突破**：

1. **nonPP4 逐折均值 0.990±0.011（2 seed 验证）**，远超 VLM 0.59+ 目标。
2. **结构性解法**：让对比信号本身携带跨试件不变量，编码器被迫学"试件不变的判别特征"。
3. **H5 oracle 根本解药**：P4a 报告的天花板不是物理不可破，而是**没找到让表征带跨试件不变量的预训练目标**。
4. **可发表贡献**（ICML/NeurIPS/NDT）：
   - **方法**：跨试件监督对比学习在 LOOCV 缺陷检测上的有效性
   - **诊断**：H5 oracle 的"表征级天花板"实际上是"SSL 任务与下游任务不对齐"问题
   - **负面证据图景完整**：P0–P5a 的"廉价杠杆"全部证伪（增强/微调/TTA/融合/形态头/改掩码/合成注入）— 而真正有效的解法（监督对比）极简（无合成数据、无新数据、仅改 SSL 任务定义）
