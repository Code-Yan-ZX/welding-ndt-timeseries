# PAUT P5d 阶段报告：Test-Time Training (TTT) — 推理时用 P1 SSL MAE 适配 test 试件 —— 负面

> 阶段：P5d（推理时在 test 试件**无标签**数据上继续微调编码器，表征级测试时适配）
> 日期：2026-08-13 ｜ 编码器：P1 SSL MAE（`experiments/runs/ssl_ae/encoder.pt`, d_model=128）
> 动机：P4a H3-TENT/BN 是**决策边界层/BN 统计**的浅层适配，失败。P5d 用 **P1 同款 SSL MAE
> 重建目标**在 test 折无标签 B-scan 上**微调编码器权重**（表征级适配），问能否跨越 H5 oracle
> 定位的"跨试件天花板"（~0.58，SSL 表征的跨试件可判别性）。
> **结果：失败**。规范头（P4a 同协议, lr=1e-3/80ep, base≈0.57）下 TTT 三档预算全负
> （-0.009~-0.038，PP7 崩塌驱动）；val-domain 对照 ≈0（非 test 特异）。

---

## 0. 路线图

### 0.1 诊断（P4a/P5/P5b 继承）

1. **H5 oracle**：SSL 特征同试件内线性 ~0.68，跨试件 0.60；**+20% test 折标签都无效**（0.583）
   → 天花板是"SSL 表征的跨试件可判别性"（表征级）。
2. **P4a H3 浅层 TTA 全败**：TENT（熵最小化）0.577/0.533、BN 重校准 0.503/0.378。
   → "问题不在决策边界层的浅层适配，而在表征层的跨试件可判别性"。
3. **P5/P5b 改造预训练目标全败**（注入/掩码/监督对比）→ 未触及的杠杆：**推理时把编码器
   表征适配到 test 试件分布本身**（Test-Time Training）。

### 0.2 假设与失败判据

| 假设 | 方法 | 预期 | 失败判据 |
|---|---|---|---|
| **H8** 表征级 TTT：在 test 无标签数据上按 P1 MAE 目标微调编码器 → 特征对齐 test 试件 → 跨过 H5 天花板 | 冻结 head（train 折训练）; 编码器在 test 折无标签 bscan 上 SSL-MAE 微调（固定预算, 不按 test AUC 调参=无泄漏）; TTT 后冻结编码器+原 head 评估 | 非PP4 逐折均值 ≥0.62 跨 3 seed | ≤ baseline 0.579（规范头） |
| TTT 机制本身 | recon loss 在 test 无标签数据上应下降（编码器确实适配了 test 分布） | recon 显著下降 | recon 不降 = 无适配 |

### 0.3 评价口径（与 P4a 同，不可变）

- 5 折 LOOCV（PP3–PP7 轮流 test），**非PP4 AUC** 主指标（逐折均值 + pooled）。
- **per-fold 严格**（P5b 教训）：head 只用 4 训练试件标签；TTT 只用 test 折无标签数据；
  TTT 预算固定，不按 test AUC 选参（无泄漏）。
- 多 seed（42/43/44）验证（P4a 教训：单 seed 不算数）。
- **统一规范头协议**（lr=1e-3, epochs=80，P4a baseline 0.579±0.007 同款；2026-08-13 起弃用
  旧脚本 lr=5e-4/40ep 默认协议，P5/P5b 已按规范头重跑，见 §3.4）。

## 1. 方法

### 1.1 TTT 流程（每折）

1. **head**：冻结 P1 编码器，4 训练试件标签训二分类头（与 baseline 完全同协议），val-AUC 早停。
2. **decoder warm-up**：P1 只存了 encoder，补 decoder 在**训练试件**无标签数据上预热
   （只训 decoder，冻结 encoder；用训练域数据合法，不接触 test 标签）。
   → 保证 TTT 的梯度是"适配 test 域"，而非"从零学解码"（去混杂）。
3. **TTT**：在 **test 折无标签 bscan**（归一化用 train 折统计，与 eval 一致）上微调 encoder
   （decoder 快 LR 跟随）。固定预算（ttt-steps ∈ {10, 30, 60}，enc_lr=1e-4, dec_lr=1e-3）。
4. **eval**：TTT 后冻结编码器 + 步骤 1 的 head，在 test 折出 AUC。同脚本输出 no-TTT 对照
   （同一 head / 同一 seed → 直接 delta）。

### 1.2 对照

- **val-domain TTT**：同样预算、把 TTT 用在 **val 折（源域子集）**无标签数据上。若 val-TTT
  也提升 → 增益是"通用 SSL 微调"而非 test 域适配；若 test-TTT ≫ val-TTT → 真 test 域适配。

### 1.3 部署

- 环境：`.venv_p2`，GPU2（RTX 4090 D）。新脚本 `scripts/paut_p5d_ttt_loocv.py`。
- warm-up 600 步（源域 recon 收敛到 ~72-78），TTT 30 步≈12.8 epochs/test 折。

### 2.2 规范头 val-domain 对照（ttt=30, seed 42）

非PP4：base 0.565 → ttt 0.564（Δ=-0.001）；pooled 0.601→0.606（Δ≈0）。

**TTT 对源域 val 折也做了同样的 recon 适配（87.9→77.5 等），但对 AUC 无任何影响**
→ 增益不是"通用 SSL 微调"，规范头下 test 域 TTT 反而净负。

## 3. 关键发现

### 3.1 PP7 崩塌机制（规范头 ttt=30: seed 42 最甚 -0.243, 3 seed 均值 -0.162）

- PP7 缺陷率仅 13.8%（86% clean），TTT 重建目标被 clean 样本主导 → 编码器把 PP7 的
  "常规本底"重建得更好，但缺陷样本的特征被推向远离决策边界 → head 在缺陷上失效。
- 这是 TTT-MAE 在**缺陷稀疏 test 试件**上的固有风险：SSL 目标（重建主导模式）与
  缺陷检测目标（识别少数异常）不一致。

### 3.2 与 H5 oracle 严格互证

- H5 已证"+20% test 标签都无效"；P5d 补证"**test 试件全部无标签数据 + 表征级适配也无效**"。
- recon 下降证明适配确实发生，但跨试件判别力未增加 → **天花板是 SSL 表征的跨试件可判别性，
  不是"编码器没见过 test 试件"**。TTT 能适配"test 试件长什么样"，但补不了"缺陷 vs 本底
  在该试件上的可分性"。

### 3.3 方法学注记：P5/P5b 已统一为规范头协议

- P5/P5b 原 LOOCV 脚本默认头协议（lr=5e-4/40ep）与 P4a 规范基线（lr=1e-3/80ep）不一致，
  属跨协议比较。已按规范头重跑 P5（0.545±0.003）/ P5b（0.487），结论不变
  （见 README 汇总表，2026-08-13）。

---

## 4. 结论

**P5d 为负面结果**，P4a H3 浅层 TTA → P5d 表征级 TTT 均无法跨越 H5 天花板：

1. **规范头下 TTT 全预算为负**（-0.009~-0.038），PP7（缺陷稀疏试件）崩塌驱动。
2. **val-domain 对照 ≈0** → 增益非 test 特异，规范头下 test 域 TTT 净负。
3. **TTT 机制成立但无判别力增益**：recon 一致下降（适配发生），但跨试件缺陷可判别性未增
   → 与 H5 oracle（+20% 标签无效）互证：**天花板是表征级，不是"模型没见过 test 试件"**。
4. **P0–P5d 完整证据图景收口**：所有形式测试时适配（TENT / BN / SSL-MAE-TTT）、所有
   SSL 预训练目标改造（掩码 / 深度掩码 / 缺陷注入 / 监督对比）、融合 / 微调 / 形态头 /
   VLM 均未稳健突破 ~0.58（规范头基线 0.579）。

**翻盘点依旧资源型**（P5 结论不变）：新试件数据（解耦"缺陷存在"与"试件缺陷率"）或
CIVA 级物理保真合成。
